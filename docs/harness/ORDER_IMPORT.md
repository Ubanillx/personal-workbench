# 订单节点导入（唛头 / 验货）

> 目的：把亿星里跟进的订单，按固定提前量倒推出节点 deadline，生成任务进入任务进展与日历。
> 第一版只覆盖截图里框住的两段：**唛头**、**验货**；订舱等节点后续按同一模型扩展。

## 1. 输入文件

Excel（`.xlsx`）。支持两种常见形态：

**跟单跟进表**（当前实际使用的表）：一个客户一个工作表，第 1 行是「订单信息 / 工作流程查对」分组，
**第 2 行才是表头**。以下列会被识别，其余列忽略：

| 列             | 必填 | 说明                                                                 |
| -------------- | ---- | -------------------------------------------------------------------- |
| 客户合同号     | ✅   | 也接受「合同号 / 合同编号 / 订单号」                                 |
| 工厂           | 建议 | 「工厂名 / 工厂名称 / 供应商」也接受；缺失时任务说明里标注           |
| 工厂合同交货期 | 建议 | 也接受「工厂交期 / 工厂货期 / 工厂交货期」；缺失时唛头无法计算       |
| 客户合同ETD    | 建议 | 也接受「客户交期 / 客人交期 / 客户交货期」；缺失时只剩按工厂交期倒推 |
| 客户名         | 否   | 缺省用所在工作表名，写进任务说明                                     |
| PO号           | 否   | 写进任务说明                                                         |
| 工厂合同号     | 否   | 写进任务说明                                                         |
| 验货日期       | 否   | 只作为「计划验货日期」写进说明，不参与 deadline 计算                 |

一个工作簿里所有带订单表头的工作表会**合并解析与导入**（预览摘要会列出工作表名称与数量），
跨工作表也会做「合同号 + 工厂」去重。

**单表格式**兼容旧模板：第一张表包含 合同号 / 客户交期 / 工厂交期 / 工厂名（工厂名可选）即可，顺序不限。

日期支持 Excel 日期单元格、`YYYY-MM-DD`、`YYYY/M/D`、`M/D/YYYY` 等常见写法。

**同一个合同号可以有多行**：一个合同由多个工厂生产时，按「一行一个工厂」导出即可，每行的工厂交期分别计算
该工厂的唛头 / 验货 deadline，任务也分别生成（标题形如 `【26DE5001 华彪】唛头`、`【26DE5001 拜博】唛头`）。
只有「合同号 + 工厂」完全相同才会被提示为重复行。

导入抽屉里提供「下载订单模板 / 下载规则模板」（`GET /api/order-import/template?kind=orders|rules`），
可以直接按模板整理文件。

### 表头认不出时：手动映射

亿星导出的表头如果对不上别名（例如「编号 / 客交 / 厂交 / 供应商」），服务端不会直接报错拒绝，
而是返回 `needsMapping: true` 和每张表前 20 行的预览；抽屉随即展开映射区，让你选：

- 工作表、表头所在行；
- 「合同号 / 客户交期 / 工厂交期 / 工厂名」分别对应哪一列（合同号必选，两个交期至少选一个）。

选完点「按此映射预览」即可看到同样的预览表；映射只作用于本次导入，不落库。确认导入时把映射作为
`mapping` 一起提交。已有别名能自动识别时不会出现这一步。

### 规则文件（可选，第二个 .xlsx）

| 列       | 必填 | 说明                                                |
| -------- | ---- | --------------------------------------------------- |
| 节点名称 | ✅   | 同时作为任务维度名，例如 唛头 / 验货 / 订舱         |
| 基准交期 | 否   | 客户交期 / 工厂交期 / 较早者；缺省按工厂交期        |
| 提前天数 | ✅   | 0–365 的整数                                        |
| 计算方式 | 否   | 自然日 / 工作日；缺省自然日。工作日只跳过周六、周日 |

导入规则文件会用文件内容**整体替换**本人当前规则；不传规则文件时沿用本人已保存的规则，
从未导入过则使用默认两条（唛头、验货）。替换规则不会删除旧节点已经生成的任务。

## 2. 默认规则（可用规则文件覆盖）

| 节点 | 基准日期                    | 提前量 | deadline 示例（工厂交期 2026-12-10） |
| ---- | --------------------------- | ------ | ------------------------------------ |
| 唛头 | 工厂交期                    | 30 天  | 2026-11-10                           |
| 验货 | 客户交期 / 工厂交期里较早者 | 7 天   | 客户 11-17 ⇒ 2026-11-10              |

默认值定义在 `app/lib/order-rules.ts`；导入规则文件后，按文件里的节点与提前量生成。
需要按工作日倒推时，把规则行的「计算方式」写成工作日，例如：`验货 / 较早者 / 5 / 工作日`。

## 3. 生成的任务

- **每个「合同号 + 工厂 + 节点」一条**：标题 `【合同号 工厂名】节点名`（没有工厂列时是 `【合同号】节点名`），
  截止日期 = 该工厂的 deadline，负责人与发布人都是导入人，优先级 P1。
- 自动创建/复用本人的「节点名」维度，并把任务挂进去（`task_dimensions.rule_key` 标记为订单节点卡）。
- 去重键 `order_key = 合同号|节点` 加 `order_factory = 工厂名`（按导入人唯一）：重复导入只更新标题 / 说明 / 截止日期，
  不重复建任务；已归档的任务不动。
- 任务来源记为 `api`（外部系统导入），不写进度流水、不发通知。
- 缺少计算所需日期的节点会跳过，并在导入预览的「提示」列说明。

## 4. 视图行为

- **日历**：按截止日期显示全部订单节点任务，不裁剪。
- **维度看板**：同一合同多工厂的订单任务按合同号归组，组内按工厂分行（单工厂订单与手动任务保持平铺）；
  订单卡片额外显示「客户交期 / 工厂交期」一行（从任务说明解析）；
  `rule_key` 非空的订单节点卡只显示**订单任务里未来 7 天内到期**（含逾期未完成）的条目；更远或要看具体日期去日历。
- 手动任务不受该窗口影响：用户自己记在「唛头」维度下的任务仍按原规则显示。

## 5. 接口与实现

- `POST /api/order-import`（multipart）
  - `file`：订单 `.xlsx`，最大 10MB；
  - `rulesFile`（可选）：节点规则 `.xlsx`，确认导入时整体替换本人规则；
  - `mapping`（可选，JSON 字符串）：手动列映射 `{ sheetName, headerRow, columns: { contract, customerDue?, factoryDue?, factoryName? } }`，列号从 1 起；
  - 不带 `confirm=1`：解析并返回预览 `{ sheet, rows, errors, rules }`，每行的 `deadlines` 以节点名为键；
  - 表头认不出且没传 `mapping`：返回 `{ needsMapping: true, sheets, rules, errors }`，`sheets` 含每张表前 20 行 × 最多 30 列的原始单元格文本；
  - 带 `confirm=1`：写库并返回 `{ created, updated, skipped, dimensions }`；管理员需要用 `orgId` 指定归属组织。
- 解析与写入：`app/lib/order-import.server.ts`；页面入口在任务进展页头的「导入订单」抽屉。
- 迁移 `021_order_tracking.sql`：`tasks.order_key`、`task_dimensions.rule_key`；`022_order_step_rules.sql`：用户节点规则表；
  `023_order_rule_day_type.sql`：规则的计算方式（自然日 / 工作日）；`024_order_factory.sql`：`tasks.order_factory`，
  订单去重键扩展为「合同号 + 工厂 + 节点」。

## 6. 已知边界

- 已适配「跟单跟进表_林桂霞 Suki」：多客户工作表、第 2 行表头、客户合同号 / 工厂 / 工厂合同交货期 / 客户合同ETD 均可自动识别。
- 手动映射只支持「合同号 / 客户交期 / 工厂交期 / 工厂名」四列，多个工作表时一次只导入一张（自动识别路径不受此限）。
- 工作日模式只跳过周六、周日，不含法定节假日；「订周五前」这类对齐到周几的规则还没建模。
- 规则文件覆盖「节点名称 / 基准 / 提前天数 / 计算方式」四列。
- 换规则或订单从文件里消失时，旧任务不会自动删除或重算：重新导入会按当前规则更新/新建对应节点任务，旧节点任务保留，需要手动归档或删除。
