## 1. 要解决什么

| 维度         | 现在                                                                                    | 改后                                                                        |
| ------------ | --------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| 谁提交       | member 只能传自己的；manager / admin 要在表单里选「归属人」代传（admin 还可跨组织代传） | **谁登录谁就是归属人**；「归属人」字段整体消失，代传取消，admin 不提交      |
| 正文存哪     | 服务器本地 `data/uploads/reports/<reportId>/v<N>.<ext>`                                 | **只存 NAS**：`<上传根目录>/<登录用户名>/<起止日期>/<文件名>`               |
| 谁能看到正文 | 只有装了本服务、且能登录本服务的人                                                      | NAS 上有该共享目录权限的人（代价见 §11）                                    |
| 备份         | `DEBT-08`：`data/uploads/` 不在任何备份范围，DB 有元数据、文件丢了就没了                | 由 NAS 的快照 / 回收站负责；本机不再存正文                                  |
| 配置         | 无（本地目录由 `UPLOADS_DIR` 写死）                                                     | 管理员在 `/settings → WebDAV` 配一个**统一上传账号 + 上传根目录**（§4）     |
| 下载         | `fsp.readFile` 全量读本地再回传                                                         | 服务端**流式代理** `/api/reports/:id/file/:version` → NAS（顺带修掉全量读） |

一句话：**谁登录谁就是归属人；正文只存 NAS，路径按「归属人 / 周期 / 文件名」。**

## 3. 落点与命名

### 3.1 路径规则

```text
{上传根目录}/{username}/{periodStart}_{periodEnd}/{文件名}
```

以根目录 `/周报`、账号 `zhangsan`、周期 `2026-09-01 ~ 2026-09-07` 为例：

| 场景                             | 远端路径                                                  |
| -------------------------------- | --------------------------------------------------------- |
| 新建提交 `第八周周报.docx`       | `/周报/zhangsan/2026-09-01_2026-09-07/第八周周报.docx`    |
| 被退回后重传（库里 version = 2） | `/周报/zhangsan/2026-09-01_2026-09-07/第八周周报_v2.docx` |
| 同期同人再新建一份同名文件       | `/周报/zhangsan/2026-09-01_2026-09-07/第八周周报_2.docx`  |

`periodStart` / `periodEnd` 直接取周报表里的 `YYYY-MM-DD` 值（表单 RangePicker 的产出），不再二次换算周号。

### 3.2 名字清洗（三段都要过）

复用现有 `reports.server.ts` 的 `sanitizeName` 口径，并补齐目录段规则：

- 剔除控制字符与 `/`、`\`；去掉首尾空格与首尾 `.`（避免 `..` 与前导点）；
- 空段回退 `unnamed`；单段上限 120 字符，超出截断但保留扩展名；
- 用户名取 `users.username`（注册已限字符集），**仍然按同一规则清洗**——库里出现异常值时不能把路径顶穿；
- 扩展名白名单与大小限制不变，文件名主体保留原大小写。

### 3.3 撞名与版本（远端绝不静默覆盖）

上传前先决定目标名，再用 **`PUT` + `If-None-Match: *`** 让 NAS 端原子拒绝覆盖（存在则 `412`）：

| 场景        | 目标名             | 已存在时的处理                                    |
| ----------- | ------------------ | ------------------------------------------------- |
| 新建（v1）  | `{stem}{ext}`      | `{stem}_2{ext}`、`{stem}_3{ext}` … 最多试探 20 次 |
| 重传（v≥2） | `{stem}_v{n}{ext}` | `{stem}_v{n}_2{ext}`、`_v{n}_3{ext}` … 同样 20 次 |

- NAS 不支持 `If-None-Match`（返回 501 或忽略了条件头）时，回退到 `PROPFIND Depth:0` 探测存在性；
- 试探到上限 → `409 CONFLICT`「远端已存在同名文件，请改名或换一个周期」；
- **库里的 `report_files.version` 是权威**，文件名后缀只是给人看的，因此出现 `_v2_2` 属于正常结果；
- 这条规则取代了本地时代的 `flag: "wx"`（独占创建）语义。

### 3.4 `report_files.stored_name` 的新值域

| 取值                                                          | 含义                                                       |
| ------------------------------------------------------------- | ---------------------------------------------------------- |
| `webdav:/周报/zhangsan/2026-09-01_2026-09-07/第八周周报.docx` | **新式**：远端路径（相对 **WebDAV 服务根**，含上传根目录） |
| `v1.xlsx`                                                     | **旧式**：本地文件名（迁移脚本搬完并回写后不再产生）       |

三个要点：

1. 前缀复用 `shared/types/domain.ts` 的 `WEBDAV_PATH_PREFIX`（`webdav:`），与 `important_files` 的约定同源；
2. 存的是**含上传根目录的完整相对路径**，而不是「相对上传根」——这样管理员日后改根目录，老记录仍能下载（代价见 §11.3）；
3. 文件名列不加、表不加，只换 `stored_name` 的值域，**迁移 014 不动 `report_files`**。

## 4. 配置：统一上传账号（新表 + 设置页区块）

### 4.1 数据

迁移 `014_report_upload_settings.sql`（`013` 已被 `013_task_moved_event.sql` 占用），**单行**表：

```sql
CREATE TABLE IF NOT EXISTS report_upload_settings (
  id         INTEGER PRIMARY KEY CHECK (id = 1),   -- 单行表：全局只有一份
  username   TEXT    NOT NULL DEFAULT '',
  password   TEXT    NOT NULL DEFAULT '',          -- 明文，Basic 认证需要原文（同 webdav_settings）
  root       TEXT    NOT NULL DEFAULT '/周报',
  timeout_ms INTEGER NOT NULL DEFAULT 15000,
  updated_by TEXT    REFERENCES users(id) ON DELETE SET NULL,
  updated_at TEXT    NOT NULL
);
```

- **地址仍然来自 `.env` 的 `WEBDAV_URL`**（部署级，D-44 的口径不变）；
- 没有这一行 = 「周报存储未配置」→ 上传与下载（新式记录）503；
- `webdav_settings`（按账号）**原样保留**，继续给「重要文件」用，两者不共用配置、也不互相回退。

### 4.2 设置页

`/settings → WebDAV` Tab 内新增「周报上传」区块，**只对 admin 渲染**（manager 打开同一个 Tab 只看到自己那份按账号配置）：

| 字段         | 必填 | 默认    | 说明                                                    |
| ------------ | ---- | ------- | ------------------------------------------------------- |
| 用户名       | 否   | 空      | 统一上传账号；NAS 允许匿名写就留空                      |
| 密码         | 否   | 空      | **留空 = 保持已保存的密码**（页面永远不回显）           |
| 上传根目录   | 否   | `/周报` | 复用现有「选择目录」Drawer（`webdav-dir-picker.tsx`）挑 |
| 请求超时(ms) | 否   | `15000` | 单次远端请求超时                                        |

action：`save-report-upload` / `clear-report-upload` / `test-report-upload` / `browse-report-upload`（命名沿用现有 `save-webdav` 等风格）。
「测试连接」「选择目录」都**用表单当前值**去连（第一次保存前也能用），与 D-45 的既有做法一致。

| 角色    | 现在                                  | 改后               | 文案 / 状态                                                    |

### 5.2 `GET /api/reports/:id/file/:version`（下载）

顺序：

1. `getReportFile` 的权限与组织边界判定**完全不变**（跨组织 / 看不到的一律 404）；
2. `stored_name` **无** `webdav:` 前缀 → 走旧的本地读路径（兼容期，见 §6.3）；
3. 有前缀 → 用**统一上传账号**配置向 NAS `GET`，`Readable.fromWeb(...)` **流式**回传；
4. 响应头保持 `content-type`（库里 `mime_type`，缺失时按扩展名推）、
   `content-disposition: attachment; filename*=UTF-8''<原文件名>`、`content-length`（库里 `size_bytes`，未知则不设）；
5. 远端 404 → `NOT_FOUND`「文件已丢失」404（沿用现文案）；
6. 未配统一账号 / 没用 `WEBDAV_URL` → 503 `WEBDAV_DISABLED`，文案：「周报存储未配置：请联系管理员在「设置 → WebDAV」配置周报上传」。

> 现有 `WEBDAV_DISABLED` 文案（「未配置 WebDAV：请到「设置 → WebDAV」填写地址与账号」）是给「重要文件」按账号配置用的，
> 两者受众不同：周报的读者是**普通成员**，不该被指去一个他们进不去的设置页，因此新文案单独一条。

### 5.3 页面 `/reports`

- 上传按钮 / 抽屉：**admin 不渲染**（列表、筛选、审批、退回、下载照旧）；
- 抽屉里删掉「归属人」表单项，保留周期 RangePicker、类型、备注、文档；
- 列表「归属人」列保留（现在恒为提交者本人，manager / admin 看到的仍是各成员自己的）；
- 上传失败（NAS 不可达 / 409 撞名上限 / 503 未配置）在抽屉内提示并允许重试，不吞错。

### 5.4 其它端点

`GET /api/reports`、`GET /api/reports/:id`、`approve`、`return` 的**请求与响应逐字段不变**（契约无 delta）。

## 6. 数据与迁移

### 6.1 迁移清单

| 编号  | 内容                                         | 影响面                           |
| ----- | -------------------------------------------- | -------------------------------- |
| `014` | 建 `report_upload_settings`（单行，见 §4.1） | 新表；不动任何既有表 / 列 / 数据 |

`report_files` **不加列、不改结构**，只换 `stored_name` 的值域（§3.4）。

### 6.2 存量搬迁 CLI

```bash
npm run reports:migrate-webdav -- --dry-run     # 只打印计划（先跑这个）
npm run reports:migrate-webdav                  # 上传 + 回写 stored_name
npm run reports:migrate-webdav -- --purge       # 收尾：删掉本地正文与空目录
```

- 逐条处理 `report_files`：**无前缀**的记录读本地 `data/uploads/reports/<reportId>/<stored_name>`，
  按 §3.1 的新命名（版本对齐库里 `version`：v1 不加后缀，v≥2 加 `_v{n}`）PUT 到 NAS，成功后回写 `stored_name`；
- **幂等**：已有 `webdav:` 前缀的记录直接跳过，可反复跑；
- `--purge` 删除本地文件与 `data/uploads/reports/<reportId>/` 空目录；**删前必须再 `stat` 一次远端确认存在**；
- 缺本地文件、NAS 不可达、目标已存在 → 逐条记失败并汇总，**退出码非 0**，不半途而废、不静默跳过；
- 未配置统一账号 / 没有 `WEBDAV_URL` → 直接拒绝运行并提示先去设置页配置。

### 6.3 兼容期：双读

无前缀 = 本地（老记录），有前缀 = NAS（新记录）。这个过渡态有**两个不可省的用处**：

1. 迁移脚本跑之前系统照常可用，不需要「停机搬文件」；
2. **契约夹具与 SSR 冒烟不依赖外部 NAS**（见 §8）——它们跑的就是旧式记录。

兼容期何时结束：等 CLI 跑完、并确认没有无前缀记录（CLI 会打印剩余清单）后，本地读路径可以整体删除。
把「删掉本地读分支 + `UPLOADS_DIR` 只服务于迁移脚本」记为一次独立的小提交。

## 11. 风险与取舍

1. **NAS 层没有隔离**（已确认接受）：统一账号写入一个共享目录，能打开该共享的人可以看到所有人的周报——
   应用层的组织隔离（跨组织 404）仍然生效，但它管不到 NAS 界面。要收紧只能靠 NAS 自己的共享权限。
2. **提交强依赖 NAS**（已确认接受）：NAS 挂了 / 网络不通就交不了周报，没有本地兜底。
   这正是「只存 WebDAV」的直接代价，换取的是「文件天然在备份体系里、人在 NAS 上直接能翻」。
3. **存的是含根目录的完整路径**：改「上传根目录」只影响新文件，老记录仍指向旧目录。
   好处是老周报不会因为改配置而失效；代价是 NAS 上会同时存在旧根与新根两个时期的内容——**根目录定了就别改**。
4. **代理下载占应用带宽**：浏览器流量经应用转发到 NAS（换来的是权限判定与凭据不出服务器）。
   实现改为流式后内存占用与文件大小无关（顺带修掉现在「全量 `readFile`」的问题）。
5. **孤儿文件**：远端 PUT 成功但 DB 回写失败时，NAS 上会留一份没人知道索引的文件。不做自动清理，
   排查办法见 §6.3 的剩余清单与 CLI 输出。
6. **`DEBT-08` 部分关闭**：周报正文不再只存在本机（NAS 侧由 NAS 的快照 / 回收站负责），
   但 `.before-migration-*.bak` 散落问题仍在，`DEBT-08` 保留并把「周报文件无备份」一句划掉。

## 12. 回滚

- **迁移前**：`npm run db:backup`（数据库快照）+ 不跑 `--purge`（本地正文原样留着）；
- **代码回滚**：老记录（无前缀）照旧读本地，功能不受影响；新记录（有前缀）在回滚后的版本里下不了
  （远端文件仍在 NAS，可用 NAS 界面取），列表与审批照旧；
- **完全回退**：恢复备份库 + 反向把 NAS 文件拉回本地（脚本可后补 `--pull` 模式，记入 `TODO.md`，
  本次不做）。

**与设计的偏差**（都是实施中发现的，按此为准）：

1. **迁移编号 013 → 014**：`013_task_moved_event.sql` 已占用（设计文档写 013 时按当时的目录判断有误）。
2. **`safeSegment` 是「剔除」而不是「替换」路径分隔符与控制字符**：与既有 `sanitizeName` 同一口径
   （`../etc` → `etc`，而不是 `_etc`）。
3. **下载超时单独放宽**：`open()` 至少用 120 秒。`AbortSignal.timeout` 会连同**响应体**一起掐断，
   沿用浏览目录那套 15 秒会让大文件在慢速局域网上传到一半断掉。
4. **`content-length` 取远端响应头的值**（拿不到就不带该头），不再用库里的 `size_bytes`：
   流式转发时以真实远端为准，也不会因为两者不一致而截断响应。
5. **老记录的兼容分支放在 `openReportFile` 里**，并且老记录也改成流式读（`createReadStream` + `Readable.toWeb`），
   顺带修掉原来「整份读进内存」的写法。
6. **周报页的「归属人」筛选器保留**（仅 manager / admin），`listReportOwnersFor` 继续存在但语义变成
   「筛选器数据源」；被删掉的是上传表单里的归属人下拉。
7. **页面 description 改成角色中立文案**：原文案「上传周报与总结…」含子串「上传周报」，
   会让「管理员看不到上传入口」的 SSR 断言假阳性。
8. **搬迁 CLI 的 `--purge` 修过一个真实缺陷**：回写后 `stored_name` 已是远端路径，不能再拿它拼本地路径；
   已回写的记录按旧约定还原成 `v<version><ext>`（`test/db/report-storage.test.ts` 覆盖了这条）。
9. **契约用例改名**：`reports.create.managerA.proxy` → `…managerA.own`、
   `…managerA.cross-org-owner` → `…managerA.owner-ignored`（代传取消，名字要跟着说实话）。
10. **契约环境用假 NAS**（§10 方案 A）：`tools/webdav/fake-server.ts` 由 `test:webdav`、`contract:*`、
    `smoke:ui` 共用；夹具预置 `report_upload_settings` 一行，`startServer` 通过 `WEBDAV_URL` 注入地址。
