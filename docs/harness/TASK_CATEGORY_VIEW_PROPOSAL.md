# 任务自定义维度与分类展示：实施记录

日期：2026-10-14。状态：**最终方案已确认，功能已实现并通过功能与回归验证**。

第 1 至 5 节保留需求对齐过程，其中的待确认项与建议不是额外的实施承诺。**第 6 节为用户最终确认后的实施口径**，覆盖此前的未决描述。

## 1. 用户要求与图片依据

用户要求：针对具体任务增加自定义名称的类别，并以参考图片中的视图显示，先对齐细节。

两张参考图的共同结构：

- 按客户或业务事项分组，例如 CAINZ/ABS、金河、高秀、JJA、付款申请、验货申请。
- 每组有名称，下面逐行列出事项，行首显示勾选框。
- 多个分组同时展示，适合一眼浏览不同组的事项。
- 第一张有分组边框，第二张有标题高亮和任务文字强调；这些是视觉参考，不代表已确认需要自由画布或富文本编辑。

不把这项需求解释为上传图片、生成任务截图，或把任务按状态分成看板列。

## 2. 当前代码依据

- `app/routes/tasks.tsx` 当前使用表格视图，已有搜索、状态、优先级排序、任务详情和进度/验收入口。
- `shared/types/domain.ts` 的 `Task` 当前没有类别字段。
- `app/lib/task-permissions.ts` 的 `canReviewTask()` 是页面与服务端共用的验收判据。
- 现行规则不允许用直接修改任务状态的方式绕过进度和验收流程。
- 普通成员仅可见本组织内本人发布或当前负责的任务；分类展示不能改变该范围。

## 4. 已确认：类别归属

用户确认原话：“类别由所有的使用者自己进行创建管理和使用”。结合此前对个人分类与组织共用分类的说明，本次按个人分类执行。

### 个人分类（已确认）

每个账号管理自己的类别及归类，同一任务在不同账号下可有不同分类。普通成员可以整理自己可见的被分派任务，不需要获得编辑任务元信息的权限。

所有使用者（管理员、组织管理者、普通成员）都可以创建、管理和使用自己的类别。个人类别与归类不作为组织共用数据，不因管理员角色而开放管理他人的个人分类。

实现上类别与任务关联应带账号归属，不能简单在任务上新增一个所有人共用的类别字段。改派或组织变更后，旧归类不能让账号继续访问已不可见的任务；类别内计数也要按当前任务可见性计算。

本次不采用组织共用类别。

### 多类别归属（已确认）

用户确认原话：“可以放入多个类别，不同人对任务的处理不同”。

同一账号可以把一条可见任务放进多个自己的类别；不同账号的归类独立。多个卡片展示的是同一个任务，不创建任务副本，任务详情、进度、评论与验收仍关联原任务。

由此产生的展示规则：每个类别内同一任务只出现一次；类别计数按该类别内可见任务计算，页面总任务数按任务 ID 去重，不简单累加类别计数。取消一个类别关联不影响其他关联；没有任何个人类别关联时才进入该账号的“未分类”。

### 本人已处理（已确认）

用户确认原话：“本人已处理”。参考图中的勾选作为个人处理标记，不改变其他账号的个人处理标记。之前提出“勾选不修改任务进度”的建议已受到下节新增进展联动要求的影响，不能将旧建议当作最终确认；具体如何映射个人完成情况及任务进度需继续对齐。现行验收流程不因此自动取消。

卡片计数应命名为“本人已处理 / 总数”，隐藏开关应命名为“隐藏本人已处理”，不使用会暗示任务整体完成的文案。

### 跨类别同步与进展联动（新增确认）

用户确认原话：“勾选需要同步，并且需要同步到个人进展中的任务完成情况，并且在任务进展中，可以查看到对应维度的任务，进行具体的任务完成汇报”。

- 同一账号的同一任务在多个类别中共用处理标记，按“账号 + 任务”保存，不能按类别分别存完成状态。
- 个人进展中的任务完成情况必须反映该标记，不仅分类卡片相互同步。
- 任务进展需支持按本人自定义类别维度查看对应任务，并提供具体任务的完成汇报入口。
- 当前代码中有“任务进展”页面及“汇报进度”区域，未找到名为“个人进展”的独立页面；需确认该术语对应现有区域还是新增个人处理进展区。
- 勾选是否直接将本人负责的任务进度汇报为 100%、是否弹出完成说明、非负责人如何记录个人处理、取消勾选是否回退进度，以及任务进度反向同步规则，尚不能从现有回答确定。

建议允许取消个人勾选以修正误操作；不擅自回退原任务状态、不擅自通过验收。联动涉及原任务进度时必须复用现有进度服务、记录汇报流水，并遵守负责人及验收权限；若需扩展为多参与人汇报，须明确确认并修改相应权限模型。

### 页面内维度选择与可选归类（最新确认）

用户标注任务进展筛选栏中的“更新时间：最近在前”下拉控件，要求添加类似样式的类别/维度选择，并提供新建维度选项。

- 继续使用现有“任务进展”页面，不要求另建页面才能查看维度任务。
- 新建个人维度后，可在维度下拉选择器中选择；选中后，下方显示该维度对应的任务/子任务。
- 新建任务时可选择具体维度，但非必填；未填写不应阻止任务保存，已有任务允许后补归类。
- 延续此前确认的一条任务可属于本人多个维度、不同账号归类独立的规则，不将最新单数用语解释为取消多类别。
- 用户已确认“子任务就是现有列表里的一条条任务”：维度只是个人分类容器，不是父任务；其下展示现有任务，不新增父子任务层级、不复制任务、不要求录入下级任务。
- 新的维度选择只负责筛选，不复用排序字段，保留现有优先级与更新时间排序能力。

## 6. 最终确认与实现

用户确认“子任务就是现有列表里的一条条任务”，并对以下联动方式回答“符合”：

- 在现有任务进展增加个人维度下拉框、“全部维度”“未分类”及“新建维度”选项；管理入口提供新增、改名、删除。
- 所有使用者只创建、管理、使用自己的维度；同一任务可以加入本人多个维度，不影响其他账号。
- 新建任务时维度可选、可多选，也能保存后通过“设置维度”补充或取消；不复制任务、不新增父子层级。
- “本人已处理”在本人的多个维度、任务表格与详情中同步。“我的处理情况”展示按当前筛选的已处理/总数，同一任务不重复计数。
- 实际任务进度与状态单独显示，通过现有详情内“汇报进度”填写说明、提交，保持负责人和验收规则；个人勾选不修改整体进度或状态。
- 保留原表格与排序，增加可选的清单卡片展示，用于按所选维度浏览勾选事项；默认不改变原表格入口。提供“隐藏本人已处理”。
- 支持取消个人勾选；删除维度只删除该维度关联，不删除任务或处理标记。维度删除后，可通过“全部维度”重新查看任务。
- 筛选、排序、分页与统计均在当前任务可见范围内由服务端执行，个人数据持久化于 SQLite，刷新后保留。

本轮不增加自由画布、富文本高亮、手动拖动排序、类别合并或按周重置处理状态。这些是对齐时提出的可选建议，不属于用户已确认要求。

实现落点：迁移 `019_personal_task_dimensions.sql`；共享服务 `app/lib/task-dimensions.server.ts`；页面 `app/routes/tasks.tsx`；个人操作与维度管理组件 `app/components/task-dimensions.tsx`。API 清单、数据模型与权限文档同步更新。

验证依据：`test/api/task-dimensions.spec.ts` 包含个人隔离、多类别及取消、处理与进度独立、跨类别与详情同步、改派访问边界、原子归类、全量排序分页、复合外键与级联清理；契约新增 18 条，SSR 冒烟新增个人维度、个人处理与清单入口断言。
