# 新注册账号任务隔离验证

日期：2026-10-14。

## 环境与账号

使用当前正式构建产物运行真实 HTTP 服务，但数据库为隔离临时夹具。所有新账号都通过注册和登录接口创建，不直接插入账号表；通过组织邀请接口入组，不直接改账号组织。没有向正式数据库写入测试账号或任务。

| 测试账号           | 角色     | 组织     | 场景                      |
| ------------------ | -------- | -------- | ------------------------- |
| isolation_a        | 普通成员 | 阿尔法组 | 上级分派 + 本人创建       |
| isolation_b        | 普通成员 | 阿尔法组 | 与 A 同组但无关，互不可见 |
| isolation_c        | 普通成员 | 贝塔组   | 与 A/B 跨组，互不可见     |
| isolation_unjoined | 普通成员 | 无组织   | 不能读取任务列表          |

另使用夹具中的全局管理员及两个组织管理者执行邀请、分派和管理权限核验。新建 6 条普通任务（每个入组用户 1 条分派、1 条自建）及 1 条管理员发布给 A 的私密任务。账号与任务随临时环境清理，不作为正式可登录账号保留。

## 结果

- 初始任务列表：A/B/C 各仅见本人的 2 条任务，首页数量和数据与列表一致。表格、清单和首页均不含无关用户的任务内容。
- 篡改负责人、组织筛选或归档参数不能扩大范围；按其他用户任务标题搜索不能得到隐藏任务。
- 同组无关任务的评论、时间线和个人维度接口返回 403；跨组返回 404，错误响应不含任务标题。猜测任务 ID 打开详情不会展开任务内容。
- 66 次 API 越权写操作及 36 次页面 action 越权写操作全部拒绝，核验任务、评论、事件、进度流水、维度关联和个人处理表保持不变。
- 本人可汇报本人负责的任务；组织管理者可管理本组普通任务，不能读取其他组织任务；管理员跨组可见。
- 管理员发布给 A 的私密任务只有 A 与管理员可见；B 和本组管理者不可见。
- 把管理者发布给 A 的任务改派给 B 后，A 立即失去列表、清单、首页、时间线和历史通知的可见性，B 可见。
- A 本人创建的任务改派给 B 后，A 作为发布人仍可见，但不能替 B 汇报进度。这是已确认的“发布人或负责人可见”规则，不是无关用户泄露。

## 回归用例

新增 `test/api/task-account-isolation.spec.ts`，5 个端到端场景；由已有 `npm run test:auth` 自动执行。既有任务可见性、SSE 通知、导入判重、个人维度和跨页排序测试同时保留。

本轮完整回归通过：数据层 31 项、WebDAV 13 项、API 契约 406 项、认证/权限/维度/新账号隔离 20 项、SSR 冒烟 150 项，均无失败。lint、四个配置的 typecheck、build、antd 官方 lint 和 format:check 通过。

结论：本次覆盖范围内未发现普通成员间的任务越权访问或修改。不把管理员/组织管理者的授权管理视图称为“所有角色完全互不可见”，也不将本次测试等同于完整安全审计。
