# WebDAV 接入（重要文件）

状态：**已实现（2026-09-11，D-41；配置拆成「地址部署级 + 凭据按账号」，D-44；文件路径改成选，D-48；远端下载，D-49）**。本文是这条链路的唯一权威口径。

> 客户端自 **D-46** 起多了两个能力——条件上传（`uploadIfAbsent`：PUT + `If-None-Match: *`）与
> 流式下载（`open`：GET）——周报正文与「重要文件」的下载（D-49）都在用
> （周报见 [`REPORTS_WEBDAV.md`](REPORTS_WEBDAV.md)）。两者共用同一个客户端与同一个 `WEBDAV_URL`，但配置与用途互不影响。

## 1. 做了什么

「重要文件」原本只是一张**路径索引**（`important_files.file_path` 存本机路径，页面上只能复制路径）。
现在它多了一个**可选**的 WebDAV 通道：

| 能力         | 交互                                                                                                                                     |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------- |
| 浏览远端目录 | `/files` →「浏览 WebDAV」→ 面包屑 + 「上一级」+ 目录表格（名称 / 大小 / 修改时间）+ **本目录内筛选**                                     |
| 选文件入索引 | 目录里点文件的「选择」→ 直接写一条 `important_files`（`file_path` = `webdav:<相对路径>`）                                                |
| 选文件进表单 | 新建 / 编辑抽屉里点「选择文件」→ 面包屑浏览 → 选中的文件填进表单（名称空着时自动用文件名），**保存才落库**（D-48）                       |
| 上传文件     | 选择器里「上传到当前目录」→ 远端 PUT（同名覆盖），可勾选「同时登记到索引」                                                               |
| 看文件情况   | 列表新增「文件情况」列：`可访问 / 远端已不存在 / 未检查` + 大小 + 修改时间                                                               |
| 下载         | 远端条目带「下载」（D-49）→ `GET /api/files/:id/download` 服务端**流式代理**，`content-disposition` 直落浏览器；本机路径条目没有下载入口 |
| 配置         | **地址**在 `.env` 的 `WEBDAV_URL`；**用户名 / 密码 / 根目录 / 超时**在 `/settings` →「WebDAV」Tab（可「测试连接」，保存即时生效）        |

**不配 WebDAV 也能看**：本账号没在设置页登记过时，远端入口整块隐藏、「选择文件」与「下载」不显示；
已有索引照常查看、复制，但新增 / 改路径 / 下载需要先配置。

## 2. 配置：地址部署级，凭据按账号

配置刻意拆成两半——**一个团队通常共用同一个 NAS，但每人用自己的 NAS 账号**：

| 部分                                      | 存在哪                                     | 怎么改                           |
| ----------------------------------------- | ------------------------------------------ | -------------------------------- |
| **地址**（`http(s)://host:port/path`）    | `.env` 的 `WEBDAV_URL`（部署级、全员共用） | 改 `.env` 后**重启服务**         |
| **用户名 / 密码 / 浏览根目录 / 请求超时** | 数据库 `webdav_settings`（一账号一行）     | `/settings?tab=webdav`，即时生效 |

设成 `WEBDAV_URL` 的那一行（`.env.example` 里有模板）：

```dotenv
WEBDAV_URL=http://192.168.0.242:5005
```

设置页表单里的字段（地址那一栏是**只读展示**的）：

| 字段         | 必填 | 默认    | 说明                                                                         |
| ------------ | ---- | ------- | ---------------------------------------------------------------------------- |
| 用户名       | 否   | 空      | Basic 认证用户名；NAS 允许匿名访问就留空                                     |
| 密码         | 否   | 空      | Basic 认证密码；**留空 = 保持已保存的密码**（页面永远不回显密码）            |
| 浏览根目录   | 否   | `/`     | 可浏览根（相对 WebDAV 地址）；**点「选择目录」在远端层级里挑**，不用手写路径 |
| 请求超时(ms) | 否   | `15000` | 单次远请求超时；**状态探测另有 4 秒上限**，避免拖慢页面加载                  |

「浏览根目录」刻意做成**选**而不是**填**（D-45）：点「选择目录」打开一个 Drawer，
里面是实时的远端目录层级（面包屑 + 上一级 + 只列子目录），点一下就填好。
选择器用**表单当前值**去连（第一次配置时凭据还没落库也一样能用），
并且服务端把它浏览的 `basePath` 固定成 `/`——要挑一个根，就必须能一路往上走到服务根。

> 客户端仍然保留 Linux / Windows 路径的归一化（`normalizeWebDavRoot`，见 §4 第 10 条），
> 但那现在是**服务端兜底**：界面不再要求用户写路径，会走到那里的只有 API / 直接改库这类情况。

要点：

1. **地址为什么进环境变量**：D-43 曾经把地址也做成按账号保存（理由是「不同的人可能用不同的 NAS」），
   实际上团队共用一台 NAS，地址没必要每人填一遍。于是 D-44 把地址上收到部署级，并删掉了
   `webdav_settings.url` 这一列（迁移 `012`）——留一个「看起来还能配地址」的死列更容易误导人。
2. **两件事都要满足才接入**：`WEBDAV_URL` 配好 **且** 本账号在设置页保存过一次。
   后者是刻意的：没打算用 WebDAV 的人不该在每次打开「重要文件」时被远端探测拖慢，
   也不该看到「远端不可达」的告警。所以**配了地址不会自动对所有人开放**。
3. **凭据不外泄**：密码明文入库（Basic 认证需要原文），但只进 `Authorization` 头；页面只拿到 `hasPassword`，
   响应体 / 日志里都不带密码。
4. **权限与文件库一致**：能进 `/settings` 的是管理员与组织管理者（普通成员进不来），
   能进 `/files` 的也是这两类人，所以配置入口与使用入口的门槛一致。

### 2.1 `.env` 是怎么被读到的

`.env` 会被**自动加载**（Node 内置 `process.loadEnvFile`，不引第三方依赖；见 `server/src/config/env.ts` 的 `loadDotEnv`）：

| 入口                    | 加载方式                                                                                |
| ----------------------- | --------------------------------------------------------------------------------------- |
| `npm run serve` / `dev` | package.json 里带 `--env-file-if-exists=.env`（`HOST` / `PORT` 要赶在适配器启动前生效） |
| 服务进程内的配置读取    | `appConfig()` 里的 `loadDotEnv()`（`DATABASE_PATH` / `UPLOADS_DIR` / `WEBDAV_URL` …）   |
| `npm run user:*` 等 CLI | `server/src/cli/support.ts` 里的 `loadDotEnv()`                                         |

两条固定的优先级规则：

1. **已经存在的进程环境变量优先于 `.env`**（`process.loadEnvFile` 不覆盖已有变量），
   所以 `$env:PORT=18000; npm run serve` 这种临时覆盖始终有效；
2. **没有 `.env` 是正常情况**（该文件被 gitignore）：静默跳过，不影响启动。

### 2.2 「文件路径」只能**选**（D-48）

「浏览根目录」的 D-45 思路原样搬到了「重要文件」的新建 / 编辑抽屉：

1. **主路径是选**：文件路径字段右边是「选择文件」——打开一个 Drawer（面包屑 + 上一级 + **本目录内筛选** + 目录表格），
   点文件行的「选择」即把 `webdav:<相对路径>` 填进表单；**文件名称还空着时自动用文件名**（用户已改过的说法不覆盖）。
   选中并不马上入库——名称、分类、所属组织在点「保存」前都还能改，这与「浏览 WebDAV」的「选中即登记」是两回事。
2. **编辑时定位到原地**：编辑一条远端索引时，选择器直接打开在它所在的目录；表单里当前指向的那一行标「当前」，
   换文件就是点一下别的行。
3. **只能选，没有手写入口**：字段只读，路径只能来自选择器（浏览器读不到本机磁盘、服务端也不该为此暴露文件系统）；
   没配 WebDAV 的账号「选择文件」置灰，提示先到设置页保存一次账号——已有的本机路径索引照常显示、复制，
   只是不再新增。
4. **不搞第二套列目录**：`WebDavFilePicker`（选进表单）与 `WebDavUploadPicker`（浏览 WebDAV：选中即登记 + 上传）
   共用 `app/components/webdav-browser.tsx` 的同一份浏览逻辑；两个抽屉都走 `/api/webdav`，
   权限与边界和 §4 完全一致。

> 实现细节：选择器挂在表单抽屉**里面**（`FormDrawer` 的 `afterForm`）——antd 会给嵌套浮层 +100 层级，
> 保证它稳稳盖在表单之上，不依赖两个同层抽屉的 DOM 顺序（CODE_STYLE §10.7 第 2 条）。

## 4. 边界与安全

1. **路径不能越界**：所有远程路径拆成段处理，拒绝 `..`、`.`、空段、绝对 URL、反斜杠、`?`/`#`/`\0`，
   再逐段 `encodeURIComponent`；服务器返回的 href 必须先与「地址的 path + 浏览根」逐段比对，
   对不上的一律丢弃（防止恶意/异常服务端把索引写成越界路径）。非法路径在**发请求之前**就被拦下。
2. **凭据不出服务端**：账号密码只进 `Authorization` 头；页面 / API 响应里没有它们，
   `webDavSettingsView` 只暴露 `hasPassword`，地址也不允许内嵌凭据。
3. **权限与文件库一致**：`/api/webdav` 用 `requireManager`——管理员与组织管理者可用（普通成员 403），
   未登录 401，未配置 503。页面入口受 `requireManagerOrRedirect` 保护。
4. **组织边界**：隔离单位仍然是 `important_files.org_id`（谁登记、哪个组织看）。
   地址既然全员共用，`webdav:` 索引对所有人指向**同一个远端**；各人能看到的**范围**由各自的 NAS 账号权限决定。
5. **不做远端删除**：误删不可恢复，删文件请用 NAS 自己的界面。
6. **上传上限 100MB**：multipart 会被整体读进内存，超过返回 413 `FILE_TOO_LARGE`。
7. **明文 http 会把凭据裸奔在局域网**：能用 https 就用 https；服务本身仍是本机 / 局域网工具，不要暴露到公网。
8. **错误分类**：远端连不上 → `WebDavError.unreachable`（页面提示检查地址/网络）；401/403 → 提示检查用户名密码；
   404 → 「远端路径不存在」；远端 5xx → 502。响应体不带到页面，避免噪音与信息泄露。
9. **地址非法不让服务起不来**：`WEBDAV_URL` 缺失或写错时，`webDavAddress()` 只返回错误文案
   （设置页显示 + 禁用保存），WebDAV 通道整体不可用，其余功能不受影响。
10. **浏览根目录的归一化是服务端兜底**：`normalizeWebDavRoot` 把 Linux 写法（`/volume1/work`）、
    反斜杠写法（`\volume1\work`）、Windows 共享（`\\主机名\共享名\...`，去掉主机名与共享名）、
    盘符（`Z:\报价`）统一成 WebDAV 相对路径，并拒绝 `.` / `..`。
    界面已经改成**选**目录（见 §2），所以这条只对 API / 直接改库生效。
11. **选择器浏览的是整个服务根**：`browseWithConfig` 把 `basePath` 固定成 `/`（不沿用当前根），
    否则用户跳不出自己已配的目录、也就换不了根。可见范围由 NAS 账号权限决定，与保存后的浏览一致。
12. **「选择文件」用的是已保存的配置**：走 `/api/webdav`（`browseRemote` → 当前账号的 `webdav_settings`），
    未配置时按钮置灰（页面提示去设置页保存），不会出现「表单能用但远端没接」的假入口；
    选择只是把 `webdav:` 路径写进表单，不下载、不复制远端内容。
13. **下载与文件库同一套边界（D-49）**：`requireManager` + `locateFile` 组织边界（跨组织 / 不存在 404）；
    本机路径的索引 400（服务端读不到本机磁盘）；远端走**流式代理**，凭据不出服务端，
    文件名用远端真实文件名（`filename*=UTF-8''…`），`content-length` 只在远端给出时带上；
    下载是纯 GET，不在响应里顺带写「最近使用」（副作用留在显式操作里）。

## 5. 已知取舍

| 取舍                             | 原因与影响                                                                                                                                        |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| 地址是全局的，不能按人连不同 NAS | 这正是 D-44 的目的（团队共用一台）；代价是**想连第二台 NAS 就得改 `.env` 并重启**，不能两个地址并存                                               |
| 改地址要重启服务                 | 环境变量在进程启动时读取。凭据 / 根目录 / 超时仍然是即时生效的，只有地址需要重启                                                                  |
| 配了地址不会自动对所有人开放     | 每人要在设置页保存一次（见 §2 第 2 条），换来的是「没在用的人不被远端探测拖慢」                                                                   |
| 状态探测只查前 10 条             | 每条一次 PROPFIND；页面加载不能被远端拖死。超出的条目显示「未检查」（`webdav.server.ts` 的 `PROBE_LIMIT`）                                        |
| 不缓存远端状态                   | 每次页面加载重新探测（并发 4）；本机↔NAS 延迟可接受，避免引入过期数据与失效逻辑                                                                   |
| 同名上传直接覆盖                 | WebDAV PUT 的默认语义；需要版本化就靠 NAS 自己的快照/回收站                                                                                       |
| 密码明文入库                     | Basic 认证需要原文；本机 / 局域网工具，不上公网，不共用系统账号                                                                                   |
| 索引与远端可能脱节               | 远端文件被移动 / 删除后索引仍在，靠「文件情况」列显示「远端已不存在」，不自动清理索引                                                             |
| 本机路径不再有新增入口           | 界面改成纯选择后，浏览器读不到本机磁盘、服务端也不为此暴露文件系统，本机 / 共享盘路径只能作为老数据存在；已有的索引仍可看、可复制、可改名称与分类 |
| 下载只覆盖远端条目               | 本机路径的索引服务端读不到，只能复制；「下载」与「选择」一样只服务 NAS 上的文件                                                                   |

> 历史：D-43 曾按账号保存地址，当时记的取舍是「换账号后 `webdav:` 索引可能指向另一个远端」。
> 地址上收到部署级之后这个问题自然消失了（不再需要把「配置 id」写进索引）。

## 6. 未做的部分（下一步候选）

- **预览 / 在线打开（重要文件）**：下载（D-49）已是流式代理；要进一步做「在浏览器里直接预览」需要
  `content-disposition: inline` 与格式白名单（防止把 HTML 当页面渲染成存储型 XSS）。
- **远端删除 / 重命名 / 新建目录**：客户端已有 MKCOL 能力（上传时补建父目录用），但没有对外暴露。
- **断点续传与并发上传队列**：当前是「一次一个文件、整块读进内存」。
- **远端文件搜索**：现在只能在当前目录里看，没有递归搜索。
- **多地址 / 多 NAS**：现在一个部署只能接一台（见 §5 第一条）；要支持多台得把「连接」重新变成一等实体。

## 7. 怎么验证

```bash
npm run test:webdav        # 13 项：路径防护、PROPFIND 解析、列目录、basePath 过滤、stat/ping、上传补建与覆盖、条件上传、流式下载
npm run test:api           # 324 条契约（含 webdav.* 6 条与 files.download.* 6 条：401 / 403 / 400 / 503 / 404）
npm test                   # 全量（db + webdav + api + auth + ui = 463 项）
```

手动走查（需要一个真实 WebDAV）：

1. 在 `.env` 里写好 `WEBDAV_URL`（例如 `http://192.168.0.242:5005`）→ 重启服务；
2. 进 `/settings?tab=webdav`：地址那一栏应显示 `.env` 里的地址且**不可编辑**；填用户名 / 密码 →
   点「选择目录」应弹出远端目录层级（面包屑 + 子目录列表）→ 逐级点进去选一个目录 → 根目录那一栏自动填好；
3. 「测试连接」提示「连接成功」→「保存」，标签变成「已保存到本账号」；
4. 回到 `/files`，标题变成「从 WebDAV「/xxx」直接浏览、选择与上传」；
5. 「浏览 WebDAV」→ 进子目录（可用「在本目录内筛选」）→ 选一个文件 → 列表出现该条并显示大小 / 修改时间 /「可访问」；
   5.1 「添加文件」→ 文件名称留空 → 点「选择文件」→ 面包屑逐层进入 → 点文件行的「选择」→ 路径与名称自动填好 →
   改分类 / 所属组织 →「添加」→ 列表出现该条且「文件情况」显示「可访问」；
   5.2 「编辑」一条远端索引 → 点「选择文件」→ 选择器直接停在它所在目录、那一行标「当前」→ 换一个文件 →「保存」→ 路径已更新；
   5.3 点远端条目的「下载」→ 浏览器直接下载（文件名与远端一致，含中文也正确）；本机路径的条目没有「下载」按钮；
6. 在 NAS 上删掉那个远端文件 → 刷新页面 → 该条显示「远端已不存在」，它的「下载」按钮置灰；
7. 上传一个文件（勾选「同时登记到索引」）→ NAS 上能看到该文件，页面列表也多一条；
8. 换另一个**没登记过**的账号登录 → 它看不到远端入口（503）、「下载」也不显示，自己的配置互不影响；
9. 把 `.env` 里的 `WEBDAV_URL` 改成一个不存在的地址并重启 → 刷新 `/files` → 顶部出现「WebDAV 暂时不可达」，
   列表里远端条目的「文件情况」显示「未检查」，本机索引不受影响；
10. 删掉 `.env` 里的 `WEBDAV_URL` 再重启 → 设置页出现「还没配置 WebDAV 地址」提示，保存 / 测试连接 / 选择目录都置灰。

## 8. 排障

| 现象                               | 原因与处理                                                                                                |
| ---------------------------------- | --------------------------------------------------------------------------------------------------------- |
| 设置页提示「还没配置 WebDAV 地址」 | `.env` 里没有 `WEBDAV_URL`（或值被清空）；补上后重启服务                                                  |
| 设置页提示「WEBDAV_URL 不合法」    | 少了 `http(s)://` 协议头，或地址里内嵌了账号密码；改成纯地址，凭据填在下面                                |
| 保存时提示「还没配置 WebDAV 地址」 | 同上；地址没配好时保存会被拒绝，避免存下一行永远不生效的配置                                              |
| 点「选择目录」提示认证失败         | 先把用户名 / 密码填对再点——选择器是用**表单当前值**去连的，它不读已保存的配置                             |
| 「选择目录」里看不到某个目录       | 选择器从服务根开始浏览，能看到的范围由**这个 NAS 账号的权限**决定                                         |
| 选了目录但「重要文件」页仍是空的   | 「选择目录」只填表单，要点「保存」才落库                                                                  |
| 改了 `.env` 的地址但页面没变       | 地址是启动时读的，需要**重启服务**（凭据 / 根目录 / 超时才是即时生效）                                    |
| `.env` 里写了变量但没生效          | 确认变量名拼写（如 `WEBDAV_URL`）；同名进程环境变量会**优先于** `.env`                                    |
| 页面顶部「WebDAV 暂时不可达」      | 地址 / 端口不通、证书问题、或超时太短；先确认浏览器 / `curl` 能访问该地址                                 |
| `WEBDAV_ERROR` + 认证失败提示      | 用户名密码不对，或该账号没有这个目录的读权限                                                              |
| 「选择文件」是灰的                 | 本账号没在设置页保存过 WebDAV 配置（或 `.env` 没配好地址）：先到「设置 → WebDAV」保存一次，之后就能选文件 |
| 下载按钮不显示 / 下载得到 503      | 下载只对远端条目开放、且要求本账号已配置 WebDAV：先保存一次账号；本机路径的条目本来就只有「复制路径」     |
| 点下载得到 404                     | 远端文件已被移动或删除（列表「文件情况」也会标「远端已不存在」）：换一个还在的文件，或重新登记            |
| 文件名带中文/空格显示正常但打不开  | 客户端已逐段百分号编码；若 NAS 仍报 404，检查它返回的 href 是否与请求路径一致                             |
