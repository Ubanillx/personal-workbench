## 1. 当前项目结构

```text
personal-workbench/
|- main.js                         Electron 组合入口
|- desktop/window.js               桌面窗口配置
|- desktop/ipc.js                  Electron IPC 桥接
|- preload.js                      暴露给桌面端的安全 API
|- renderer/                       主人桌面客户端
|  |- index.html
|  |- app.js
|  `- style.css
|- share/                          助理/查看者浏览器客户端
|  |- share.html
|  |- share.js
|  `- share.css
|- server/http-server.js           局域网 HTTP 服务与共享 API
|- repositories/json-repository.js JSON 持久化与备份
|- data/workbench.json             本地运行数据
`- start-workbench.bat             启动入口
```

现在的运行方式是：Electron 启动桌面客户端，同时在主人电脑上启动 Node HTTP 服务 `0.0.0.0:17500`。桌面端通过 IPC 读写 JSON，助理端通过 HTTP 读写同一个 JSON。它适合单台主人电脑在局域网内协作，但不是一个可独立部署到公网的后端服务。

## 2. 为什么助理打不开分享链接

分享链路如下：

```text
助理浏览器 -> 主人电脑的局域网 IP:17500
          -> Windows 防火墙/安全软件/网络隔离
          -> Electron 内的 Node HTTP 服务
          -> token 校验
          -> data/workbench.json
```

因此“没有前后端分离”不是首要原因。当前页面和 API 已经有边界；真正影响可达性的原因通常是：

1. 助理与主人不在同一局域网或 VPN。`192.168.x.x`、`10.x.x.x` 等地址不是公网地址。
2. 主人电脑关机、休眠、断网，或工作台没有启动。服务只存在于 Electron 进程内。
3. Windows Defender、防护软件、公司 Wi-Fi 客户端隔离或访客网络阻止入站 TCP `17500`。
4. 当前代码只取第一个非回环 IPv4。存在 VPN、虚拟网卡、Docker、多个网卡时，生成的链接可能用了错误地址。
5. 17500 端口被占用或服务绑定失败。当前只写 `console.error`，桌面界面看不到失败原因。
6. 主人换了 Wi-Fi/网段，旧链接中的 IP 已失效。
7. 链接被复制不完整、token 被撤销，或助理已被移除。此时 API 会返回 `401`。

README 中的防火墙命令只能解决第 3 类问题，不能解决跨网络访问、应用未启动、错误 IP 或电脑休眠。若需要办公室外访问，应采用 HTTPS 加密的托管服务、VPN 或受控中继，不应直接把 17500 端口暴露到互联网。

### 已确认的代码问题

- `server/http-server.js` 允许助理通过 `POST /api/share/tasks` 发布自己的任务。
- `share/share.js` 在身份不是 owner 时隐藏 `#newTaskBtn`，所以助理端无法使用这个能力。权限和界面不一致，必须修复。
- 分享服务没有桌面端健康状态、监听地址列表、端口冲突提示、网络诊断和重试按钮。
- `renderer/app.js` 生成链接时使用 `getLanIp()` 的第一个地址，不能让用户选择实际可达的网卡。
- README 写的是 `H:\\personal-workbench\\data\\workbench.json`，代码实际使用应用目录下的 `data\\workbench.json`，备份说明不一致。
- token 放在 URL 查询参数中，容易出现在浏览器历史、截图、日志和聊天转发中。应支持轮换/撤销，并尽量换成短期会话 Cookie。

### 3.2 `新员工工作反馈每周报表-8.24-8.28.xls`

  4. 回复邮件质量
  5. 跟单的份内工作

  8. 与工厂沟通

  12. 细心
  13. 责任心

适合转换为双阶段表单：助理先填写员工自评和意见，提交后指导人填写评价并确认。服务器必须限制阶段权限，不能允许助理改写指导人的评分，也不能让提交快照被后续草稿覆盖。

## 4. 目标功能

助理在浏览器打开自己的链接后，应可以：

1. 查看分配给自己的任务和表单。
2. 发布自己的任务、记录进展、发表评论。
3. 填写每日计划、周反馈表、周工作总结。
4. 自动保存草稿，刷新或重新打开后恢复。
5. 提交后查看提交时间、版本和主人反馈。
6. 被退回时修改新版本后重新提交。
7. 在权限允许时下载生成的 Word/Excel 文件。

主人桌面端应可以：

1. 创建模板、设置版本和填写规则。
2. 指派助理、周期、截止时间和指导人。
3. 查看草稿、已提交、已退回、已通过的表单。
4. 评论、退回、通过，查看版本和操作记录。
5. 导出与原始模板结构一致的 Word/Excel 文件。
6. 查看分享服务状态、可用地址、端口和网络诊断结果。

查看者继续保持只读，可按现有规则评论可见任务；是否能下载报告需单独确认。

## 5. 建议的数据模型

不要把表单答案继续塞入 `tasks`。在现有 JSON 仓储后增加独立集合；第一阶段仍可保持单文件和原子备份。

```text
templates
  id, key, name, version, sourceFormat, schema, layout, active, createdAt, updatedAt

formAssignments
  id, templateId, assistantId, taskId?, periodStart?, periodEnd?, dueAt?, status,
  draftAnswers, submittedAnswers, revision, createdAt, updatedAt,
  submittedAt, returnedAt, approvedAt

formComments
  id, assignmentId, authorRole, authorId?, authorName, text, createdAt

formEvents
  id, assignmentId, action, actorRole, actorId?, timestamp, metadata

exports
  id, assignmentId, revision, format, path, generatedAt, generatedBy
```

表单状态固定为 `draft`、`submitted`、`returned`、`approved`。提交时保存不可变快照；退回后只能创建新修订。所有保存、提交、退回、通过、评论、导出都写入事件记录。

## 6. 建议的 API 和权限边界

保留“一键启动的 Electron 应用”，但把领域操作集中到服务层，桌面 IPC 和浏览器 HTTP 共用同一套校验，避免两端权限漂移。

```text
GET    /api/share/health
GET    /api/share/forms
GET    /api/share/forms/:id
POST   /api/share/forms/:id/draft
POST   /api/share/forms/:id/submit
POST   /api/share/forms/:id/comment
POST   /api/share/forms/:id/return
POST   /api/share/forms/:id/approve
POST   /api/share/forms/:id/export
```

服务端必须逐接口校验：身份、角色、表单指派关系、当前状态、字段可编辑范围和版本号。前端隐藏按钮不能作为权限控制。

## 7. Office 文件策略

- `.docx`：以受控模板填充标题、元信息、分节和正文，禁止执行宏或嵌入代码。
- `.xlsx`：保留已确认的工作表、合并单元格、列宽、样式、公式和单元格位置；字段映射完成后再实现导出。
- `.xls`：作为旧格式导入源，默认导出 `.xlsx`。如果业务必须得到二进制 `.xls`，需单独确认兼容组件和验收环境。
- 导出文件绑定到提交修订号，不只保存一个可能变化的本地路径。

## 8. 分享可靠性改造

1. 桌面端增加“分享服务”面板：运行/失败状态、端口、所有候选 IPv4、可复制链接、最近错误和重试。
2. 将网卡列表按物理网卡、VPN、虚拟网卡分类，让主人选择用于生成链接的地址。
3. 增加 `/api/share/health` 和本机自检；提示“应用必须保持运行、双方必须能互通、电脑不能休眠”。
4. 记录端口冲突、绑定失败、请求失败，不再只写控制台。
5. 修复助理发布任务入口：助理显示发布按钮，查看者隐藏；服务器继续执行最终权限校验。
6. token 支持轮换、撤销和失效提示；不在日志中输出完整 token URL，优先换成短期会话 Cookie。
7. 对共享 API 增加请求体限制、速率限制、安全响应头和审计记录。
8. 明确模式：默认“局域网共享”；公网访问必须经过 HTTPS + VPN/中继/托管后端的单独部署方案。

## 9. 实施阶段

### 阶段一：模板定稿

补齐新版 `.xlsx` 的工作表、列头、合并区域、公式和输出要求；把三份模板转成可审阅的字段字典。你确认后冻结模板版本。

### 阶段二：分享稳定性和已知缺陷

实现健康检查、网卡选择、端口错误提示、链接诊断，并修复助理无法发布任务的问题。先用两台设备在同一局域网验证。

### 阶段三：表单领域与 API

加入模板、指派、草稿、提交快照、退回/通过、评论、版本和审计事件；迁移时保留现有任务、待办、笔记、文件和备份。

### 阶段四：助理端与主人端

实现表单列表、响应式编辑器、字段校验、自动保存、提交确认、主人审核和查看者权限。

### 阶段五：Word/Excel 导出

按冻结的字段映射实现导出，并用 WPS/Office 打开校验内容和排版。

### 阶段六：回归与交付

完成自动化测试、局域网双设备测试、重启/断网/备份恢复测试和真实报告试填，再交付安装版本。

## 10. 验收标准

| 范围 | 必须验证 |
|---|---|
| 模板一致性 | 三份原件的标题、字段、评分档位、表头、合并区域、公式和输出位置逐项核对。 |
| 助理流程 | 助理能打开链接、发布任务、保存草稿、提交、查看退回意见并重新提交。 |
| 权限 | 助理不能查看或修改其他助理数据；不能改指导人评分；查看者不能编辑或发布。 |
| 主人流程 | 主人能指派、审核、退回、通过、评论、查看版本并导出。 |
| 持久化 | 浏览器刷新、Electron 重启、HTTP 服务重启后数据和提交快照不丢失；备份可恢复。 |
| 导出 | Word/Excel 能在 WPS/Office 打开，值落在正确位置，格式和原模板满足确认结果。 |
| 分享 | 本机、同 LAN 第二设备、错误 token、撤销 token、错误网卡、端口占用、应用关闭、电脑休眠均有可理解结果。 |
| 回归 | 任务、待办、随手记、企微收件箱、重要文件、回顾统计、评论和 JSON 备份不退化。 |

## 11. 需要你确认的决策

1. 助理是否只需在同一局域网访问，还是必须支持公司外/公网访问？
2. `.xls` 是否可以统一导出为 `.xlsx`？

4. 查看者是否允许下载已通过的 Word/Excel 报告？
5. 新版每日计划 `.xlsx` 的字段映射补齐后，是否按本文流程先做模板确认再开发？
