## 路线 B · Go 等价重写（**已放弃**，2026-09-10）

> **结论：不做。** 决策见下方 D-05。原因：与"Node 全栈单进程"的方向冲突；项目当前健康，重写的收益（运维更省心）
> 不足以抵消双栈维护成本。以下评估保留作历史记录，**不要据它开工**。

完整评估见 2026-09-10 的会话结论，要点：

| 维度     | 结论                                                                                                                                            |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| 技术映射 | 无难点：Fastify→stdlib `net/http`、`@fastify/static`+SPA fallback→`embed.FS`、multipart→`ParseMultipartForm`、`node:crypto`→`crypto/sha256`     |
| 兼容性   | 现有 `workbench.sqlite` 可直接沿用；`sha256(token)` 哈希格式一致 → 现有令牌与会话不失效；`schema_migrations` 记账方式必须照抄（重放迁移会炸库） |
| 主要风险 | 39 KB 的 `workbench.ts`（39 端点 + 三角色权限）行为等价；契约测试太薄，回归靠人眼                                                               |
| 主要收益 | 单 exe 部署、摆脱 NVM/Node 版本坑、去掉 116 MB 依赖与实验性 `node:sqlite`；空载内存 ~65 MB → ~10–25 MB，冷启动 624 ms → ~10–40 ms               |
| 主要成本 | 两周一次性投入 + 双栈过渡期 + 前端零改动的前提是 API 逐字节兼容                                                                                 |

**执行顺序（不可跳步）**：

- **Phase 0（0.5–1 天，前置）**：做「契约快照」——用现有 Node 版对 48 个端点录制 `method+path+body → status+headers+JSON`（三种身份 + 边界用例）存成 golden 文件。**没有 Phase 0 不开工。**
- **Phase 1**：Go 版先做迁移器兼容 + 认证/会话 + health，跑 golden 回放。
- **Phase 2**：分批搬路由（只读 → 写 → report）。
- **Phase 3**：`embed` 掉 `web/dist`，切单 exe；Node 版整体移入 `_archive/` 保留回退。
- **Phase 4**：观察一段时间后再决定是否删除 Node 版。

**升级触发条件**（满足任一才考虑动手）：

1. Node/NVM 环境问题再次造成实际停摆；
2. 需要把服务长期部署到非 Windows 或无人值守环境（单 exe 收益放大）；
3. `node:sqlite` 实验 API 出现破坏性变更，被迫升级 Node；
4. 路线 A 的还债已完成，且你有连续两周的整块时间。

**（以上触发条件现已全部失去意义：路线 B 已放弃。若将来重新考虑，先读 `FULLSTACK_MIGRATION.md`——Phase 3 之后业务逻辑集中在
`app/lib/*.server.ts` 与 `server/src/`，Go 重写需要连带重做整个 SSR 页面层，成本远高于 2026-09-10 的评估。）**
