# Personal Workbench 重构前审计报告（第 1 步）

审计范围：仅读取 `README.md`、`WORKBENCH_REFACTOR_ANALYSIS.md`、`REFACTOR_HARNESS.md`、项目源代码、运行日志和用户授权的三份附件。未修改业务代码、配置文件或数据文件。

## 1. 已确认事实

### 项目和数据流

- `main.js` 是 Electron 组合入口：创建桌面窗口、注册 IPC、初始化 JSON repository，并启动 HTTP 分享服务。
- `renderer/` 是主人桌面端，通过 `preload.js -> desktop/ipc.js` 读写本地 JSON。
- `share/` 是浏览器客户端，通过 `/api/share/*` 访问主人机上的 Node HTTP 服务。
- `server/http-server.js` 同时提供静态分享页、任务查询/发布/进展/评论接口和企微任务接口。
- `repositories/json-repository.js` 将任务、待办、笔记、文件、角色 token 保存在应用目录下的 `data/workbench.json`，写入前自动保留最多 5 个备份。
- 当前没有独立部署的后端进程；HTTP 服务依赖 Electron 进程持续运行。

### 启动和共享服务

- `start-workbench.bat` 启动本地 Electron 应用。
- 应用启动后尝试监听 `0.0.0.0:17500`。
- `getLanIp()` 取第一个非回环 IPv4，生成 `http://<IP>:17500/?token=...` 链接。
- 当前本机检查中，`127.0.0.1:17500` 连接被拒绝，`netstat` 未发现监听项；`app.log` 中的“共享工作台已启动”是历史日志，不能证明当前服务正在运行。

### 权限流

- owner token 返回全部任务。
- assistant token 只返回 `assignee=assistant:<id>` 的任务，可发布自己的任务、更新自己的进度和评论。
- viewer token 只返回负责人为助理的任务，可评论，不能发布、改进度。
- 服务端有权限校验，前端隐藏按钮不是安全边界。

## 2. 分享链接故障结论

问题首要不是“前后端未分离”，而是 LAN 服务可达性和运行状态：

1. 当前服务可能未运行或启动后退出；现有桌面 UI 没有健康状态。
2. 助理必须能访问主人机的局域网 IP 和 TCP 17500；不同网段、访客 Wi-Fi、客户端隔离、VPN 路由都会失败。
3. Windows 防火墙/终端安全软件可能阻止入站 17500；现有 `fix-firewall.bat` 只能覆盖其中一种情况。
4. 多网卡/VPN/Docker 环境下“第一个 IPv4”可能是错误地址。
5. 主机换网络后旧 IP 链接失效；电脑休眠、关机或应用退出时服务不可用。
6. token 缺失、复制不完整、被撤销或助理被移除时，API 返回 `401`；页面端主要表现为登录失败或重新要求 token。
7. 端口占用/绑定失败目前只记录到控制台，用户在桌面端看不到原因。

## 3. 已确认缺陷

- 服务端允许助理发布任务，但 `share/share.js` 仅 owner 显示 `#newTaskBtn`；助理页面无法使用 README 承诺的“发布任务”。
- README 的数据路径写为 `H:\\personal-workbench\\data\\workbench.json`，代码实际使用应用目录下的 `data\\workbench.json`。
- 分享页通过 URL query token 认证，完整 token 可能出现在历史记录、截图或转发内容中。
